# Roadmap: Python Backend Developer → Junior+

Этот план составлен для старта почти с нуля. Знакомство с Python поверхностное: отдельные конструкции уже встречались, но устойчивой базы пока нет. Знания Git, Linux, алгоритмов, HTTP, SQL, баз данных, Django, тестирования, Docker и архитектуры **не предполагаются**. Каждая из этих тем изучается с основ.

Главная практическая цель — самостоятельно реализовать backend-систему автосалонов, покупателей и поставщиков из задания `Django task.docx` и выйти минимум на уровень Junior+ Python backend developer.

### День 1. Как выполняется Python-программа

#### Теория

Python-файл — обычный текстовый файл с расширением `.py`. Интерпретатор читает инструкции и выполняет их. Для начала достаточно понимать последовательное выполнение сверху вниз; внутреннее устройство интерпретатора будет позже.

```python
print("Начало программы")
print(2 + 3)
print("Конец программы")
```

`print()` выводит значение. Комментарий начинается с `#` и не выполняется:

```python
# Цена пока указана без скидки
print(31_000)
```

Отступы являются частью синтаксиса Python. Обычно используется четыре пробела.

Переменная связывает имя со значением:

```python
model = "Toyota Camry"
price = 31_000

print(model)
print(price)
```

Используй понятные имена в `snake_case`. Не называй переменные `list`, `dict`, `str`, `sum` или `input`: эти имена уже принадлежат встроенным объектам Python.

#### Упражнения

1. Выведи три отдельные строки: имя, цель обучения и название будущего проекта.
2. Создай переменные `brand`, `model`, `year`, `price` и выведи описание автомобиля.
3. Поменяй значения переменных и убедись, что вывод изменился.
4. Намеренно убери закрывающую кавычку, запусти файл, прочитай ошибку и исправь её.
5. Намеренно используй переменную до присваивания, найди имя ошибки и исправь программу.

Ожидаемый формат одного из выводов:

```text
Toyota Camry, 2024 год, цена: 31000 USD
```

### День 2. Типы, числа, строки и ввод

#### Теория

Основные типы первого блока:

- `int` — целое число;
- `float` — число с плавающей точкой;
- `str` — текст;
- `bool` — `True` или `False`;
- `None` — отсутствие значения.

```python
quantity = 3
price = 31_000
discount = 7.5
model = "Camry"
is_available = True
buyer = None
```

Тип можно посмотреть через `type()`:

```python
print(type(price))
```

Основные арифметические операции:

```python
total = price * quantity
half = price / 2
whole_part = price // 2
remainder = price % 2
square = quantity ** 2
```

Порядок вычислений меняется скобками. Значения `float` могут иметь двоичную погрешность. Денежные расчёты в итоговом проекте будут выполняться через `Decimal`, но на неделе 0 можно использовать целые суммы.

Строки можно объединять и форматировать:

```python
message = f"Модель: {model}, цена: {price} USD"
```

`input()` всегда возвращает строку:

```python
raw_price = input("Введите цену: ")
price = int(raw_price)
```

7. Повтори арифметические операции, приоритет, `//`, `%`, `**` и `round()` по странице METANIT из списка материалов.

### День 3. Сравнения, логика и условия

#### Теория

Операторы сравнения возвращают `bool`:

```python
price <= 40_000
quantity == 0
model != "Camry"
```

Логические операторы:

- `and` — истинны оба условия;
- `or` — истинно хотя бы одно;
- `not` — логическое отрицание.

```python
can_buy = price <= balance and quantity > 0
```

Ветвление:

```python
if quantity == 0:
    print("Нет в наличии")
elif price <= balance:
    print("Покупка возможна")
else:
    print("Недостаточно средств")
```

Порядок ветвей важен: выполняется первая подходящая ветвь.

### День 4. Циклы

#### Теория

Цикл `for` используется, когда известна последовательность значений или количество повторений:

```python
for number in range(1, 6):
    print(number)
```

`range(start, stop, step)` не включает границу `stop`.

Цикл `while` работает, пока условие истинно:

```python
attempts = 3

while attempts > 0:
    print(f"Осталось попыток: {attempts}")
    attempts -= 1
```

- `break` полностью завершает цикл;
- `continue` переходит к следующей итерации.

У цикла `while` обязательно должно изменяться условие, иначе получится бесконечный цикл.

#### Упражнения

1. Выведи числа от 1 до 10.
2. Выведи чётные числа от 2 до 20.
3. Посчитай сумму чисел от 1 до введённой границы.
4. Выведи таблицу умножения для выбранного числа.
5. Запрашивай положительную цену, пока пользователь не введёт подходящее число. Пока без `try/except`: сначала проверяй строку через простой допустимый сценарий.
6. Реализуй FizzBuzz от 1 до 30: для кратных 3 вывести `Fizz`, для кратных 5 — `Buzz`, для кратных обоим — `FizzBuzz`.
7. Смоделируй уменьшение складского остатка после каждой продажи и остановись, когда он станет равен нулю.

### День 5. Функции

#### Теория

Функция даёт имя законченному действию и позволяет использовать его повторно:

```python
def calculate_total(price, quantity):
    return price * quantity
```

Параметры получают входные данные. `return` возвращает результат вызывающему коду:

```python
total = calculate_total(31_000, 2)
print(total)
```

`print()` и `return` выполняют разные задачи. `print()` показывает значение человеку, а `return` позволяет программе продолжить вычисления.

Переменная, созданная внутри функции, обычно является локальной. На этом этапе функции должны получать данные через параметры, а не читать изменяемые глобальные переменные.

Простые аннотации типов помогают описать контракт:

```python
def calculate_total(price: int, quantity: int) -> int:
    return price * quantity
```

Аннотации сами по себе не запрещают передать значение другого типа — это будет изучаться подробнее позже.

#### Упражнения

Напиши и проверь функции:

```python
def calculate_total(price, quantity):
    ...

def calculate_discount(price, discount_percent):
    ...

def calculate_final_price(price, discount_percent):
    ...

def has_enough_money(balance, final_price):
    ...

def can_buy(balance, final_price, stock):
    ...

def format_receipt(model, final_price):
    ...
```

Дополнительные требования:

- функции расчёта ничего не печатают;
- названия описывают действие;
- одинаковая формула не копируется в нескольких местах;
- каждая функция проверяется минимум на трёх примерах;
- отдельно проверяются ноль и граничные значения.

### День 6. Ошибки и отладка

#### Теория

Три полезные категории ошибок:

1. **Синтаксическая:** Python не может разобрать программу.
2. **Runtime:** программа запустилась, но операция завершилась исключением.
3. **Логическая:** программа работает, но выдаёт неправильный результат.

В traceback сначала найди:

- последнюю строку с типом и сообщением ошибки;
- путь и номер строки своего файла;
- значения, участвовавшие в операции.

Пример безопасного преобразования:

```python
try:
    price = int(input("Введите цену: "))
except ValueError:
    print("Цена должна быть целым числом")
```

Не используй пустой `except:` и не скрывай неожиданные ошибки. Обрабатывай только ту ошибку, которую понимаешь.

Для простой отладки временно выводи значения и их типы:

```python
print("DEBUG:", price, type(price))
```

После исправления временный вывод удаляется.

#### Упражнения

1. Исправь `SyntaxError`, `NameError`, `TypeError`, `ValueError` и `ZeroDivisionError` в отдельных маленьких примерах.
2. Напиши функцию `read_positive_integer()`, которая повторяет ввод до получения положительного целого числа.
3. Запрети скидку меньше 0 и больше 100.
4. Найди логическую ошибку в формуле `price - discount_percent` и объясни правильную формулу.
5. Добавь понятные сообщения для ошибочного ввода цены, остатка и баланса.

### День 7. Мини-проект «Калькулятор покупки автомобиля»

Программа должна запросить:

- имя покупателя;
- марку и модель автомобиля;
- цену одной единицы;
- скидку в процентах;
- количество покупаемых автомобилей;
- остаток на складе;
- баланс покупателя.

Программа должна:

1. Проверить корректность числового ввода.
2. Запретить отрицательные значения.
3. Проверить диапазон скидки от 0 до 100.
4. Рассчитать базовую и итоговую стоимость.
5. Проверить складской остаток.
6. Проверить баланс покупателя.
7. Вывести решение и точную причину отказа.
8. При успехе вывести чек и оставшиеся баланс/остаток.
9. Не использовать глобальные переменные.
10. Разделить расчёты минимум на четыре функции.

Пример успешного сценария:

```text
Покупатель: Anna
Автомобиль: Toyota Camry
Количество: 2
Стоимость без скидки: 62000 USD
Скидка: 10%
Итого: 55800 USD
Покупка разрешена
Остаток баланса: 14200 USD
Остаток на складе: 1
```

Обязательно проверь сценарии:

- товара достаточно и денег достаточно;
- товара недостаточно;
- денег недостаточно;
- денег и товара недостаточно одновременно;
- скидка 0%;
- скидка 100%;
- количество равно нулю;
- вместо числа введён текст.

### Неделя 19. Три задачи итогового проекта

1. **Закупка для автосалонов каждые 10 минут.** Сначала учитывать предпочтения, затем спрос за 30 дней. Рассчитывать средние продажи в день и запас в днях. Покупать при запасе до 2 дней, не закупать при запасе на 14 дней. Выбирать минимальную итоговую цену с учётом акции и скидки лояльности. Проверять баланс и остаток поставщика.
2. **Пересчёт лучших поставщиков каждый час.** Для каждой модели сохранять выбранного поставщика, итоговую цену, причину выбора и факт изменения.
3. **Обработка Offer покупателя.** Работать только с активным пользователем, положительным балансом и подтверждённым email. Искать активный автосалон с нужной моделью, остатком и ценой не выше максимальной. Приоритет: минимальная цена, активная акция, затем лучшая история отношений.

Для всех задач обязательно:

- `transaction.atomic`;
- блокировки нужных строк через `select_for_update`;
- детерминированный порядок блокировок;
- идемпотентный ключ или защищённый переход состояния;
- retry только для временных ошибок;
- структурированные логи;
- отдельные unit- и integration-тесты.

```text

apps/

  accounts/      пользователь, роли, подтверждение email
```

Рекомендуемые правила зависимостей:

- views принимают HTTP-запрос и вызывают use case;
- serializers отвечают за формат и входную валидацию, но не за длинные сделки;
- бизнес-операции находятся в `services.py`/use-case модулях;
- сложные запросы чтения находятся в `selectors.py` или custom QuerySet;
- Celery task остаётся тонкой обёрткой над идемпотентным сервисом;
- signals не заменяют явный бизнес-процесс;
- модели не импортируют views, serializers и Celery tasks.

#### Дополнительные подходы к качеству и надёжности

- [ ] Property-based testing, например Hypothesis.
- [ ] Mutation testing, fuzzing и тестирование контрактов.
- [ ] Углублённое тестирование конкурентного и асинхронного кода.
- [ ] Измерение производительности и защита от регрессий производительности.

#### Направления Python вне цели этого backend-roadmap

- [ ] GUI и desktop-разработка: Tkinter, Qt и другие GUI-фреймворки.
- [ ] Data Science, NumPy/Pandas, научные вычисления и машинное обучение.
- [ ] Разработка игр, компьютерная графика и мультимедиа.
- [ ] Embedded Python и MicroPython.
- [ ] PyPy, GraalPy, Jython и другие реализации Python на углублённом уровне.

После завершения проекта этот backlog нужно пересмотреть: удалить уже освоенное на практике, расставить приоритеты и превратить выбранные группы в новые недели. До этого флажки не закрываются за одно прочтение — для зачёта каждой темы понадобятся теория, самостоятельный код, проверка и отдельная запись в журнале оценки.

## Что пока не должно тормозить проект

До первого релиза не нужно глубоко изучать:

- темы из отложенного Python backlog выше;
- все алгоритмы сортировки наизусть;
- MongoDB и DynamoDB;
- Kafka Streams и кластеризацию RabbitMQ;
- микросервисы, SAGA, event sourcing и CQRS;
- глубокий AWS, Kubernetes и Terraform;
- полноценный frontend.

Эти темы важны для кругозора и следующего уровня, но проект из задания является модульным Django-монолитом и не требует преждевременного усложнения.
