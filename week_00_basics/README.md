# Неделя 0: абсолютная база Python

Это отдельный учебный модуль для старта почти с нуля. Здесь не предполагается знание Git, терминала, алгоритмов, SQL, Django или тестирования.

## Файлы модуля

- [THEORY.md](THEORY.md) — теория с примерами и важными нюансами;
- [PRACTICE.md](PRACTICE.md) — задания, тестовые сценарии и правила сдачи;
- [ASSESSMENT.md](ASSESSMENT.md) — оценки, ошибки и рекомендации после проверки;
- [notes.md](notes.md) — личные заметки и вопросы ученика;
- `day_01_first_program.py` — запуск файла, вывод, переменные;
- `day_02_types.py` — типы, числа, строки и ввод;
- `day_03_conditions.py` — сравнения, логика и условия;
- `day_04_loops.py` — циклы;
- `day_05_functions.py` — функции;
- `day_06_errors.py` — ошибки, проверка ввода и отладка;
- `day_07_car_purchase.py` — итоговый мини-проект.

## Как проходить модуль

Иди строго по дням. Каждый «день» является учебным этапом и при необходимости может занять несколько реальных дней.

Для каждого этапа:

1. Прочитай соответствующую главу в `THEORY.md`.
2. Перепечатай и запусти маленькие примеры самостоятельно.
3. Выполни задания из `PRACTICE.md` в соответствующем `.py`-файле.
4. Проверь все обязательные сценарии.
5. Удали временный отладочный вывод.
6. Напиши в конце файла небольшой блок самооценки в комментариях.
7. Сообщи мне, какой день готов к проверке.
8. После проверки исправь замечания в том же файле.

Не нужно присылать код сообщением: достаточно написать, например, «проверь день 2». Я прочитаю файл проекта и внесу результат в `ASSESSMENT.md`.

## Самооценка в конце каждого файла

Добавляй этот блок и заполняй его честно:

```python
# Самооценка
# 1. Что было самым сложным:
# 2. Что пришлось искать в документации:
# 3. Какой фрагмент я пока не могу объяснить:
# 4. Сколько времени заняла работа:
```

Это не влияет на оценку отрицательно. Наоборот, умение точно назвать непонятное ускоряет обучение.

## Правила выполнения

Можно:

- перечитывать конспект;
- запускать код сколько угодно раз;
- использовать встроенную справку и официальную документацию;
- задавать вопросы о непонятном поведении;
- делать несколько попыток.

До первой проверки нельзя:

- копировать готовое решение целиком;
- использовать библиотеки, которых нет в задании;
- заменять решение одной неизвестной встроенной функцией без понимания;
- оставлять код, который ты не можешь объяснить;
- изменять файл `ASSESSMENT.md` самостоятельно, кроме явно отмеченного блока ученика.

## Процесс проверки

Проверка каждого дня использует единую шкалу из `PRACTICE.md` и корневого `AGENTS.md`:

| Категория | Баллы |
|---|---:|
| Корректность результата | 0–3 |
| Выполнение условий задания | 0–2 |
| Граничные и ошибочные сценарии | 0–2 |
| Читаемость и имена | 0–1 |
| Понимание и самооценка | 0–1 |
| Самостоятельность исправлений | 0–1 |
| **Всего** | **10** |

Статусы:

- **Не начато** — код ещё не сдавался;
- **На проверке** — первая версия готова;
- **Нужны исправления** — есть обязательная доработка;
- **Условный зачёт** — основа понята, оставшиеся рекомендации переносятся в повторение;
- **Зачёт** — можно двигаться дальше;
- **Уверенный зачёт** — требования выполнены и понимание подтверждено.

Оценка первой попытки сохраняется. После исправлений отдельно фиксируется итоговая оценка — так будет виден рост.

## Когда можно переходить дальше

На следующий день можно переходить, если:

- программа запускается без необработанного падения в обязательных сценариях;
- выполнены все обязательные задания;
- итоговая оценка не ниже 7/10;
- нет критического непонимания базовой конструкции текущего дня.

Для завершения всей недели нужно:

- получить не меньше 7/10 за каждый день;
- получить не меньше 8/10 за итоговый проект;
- исправить все критические замечания;
- устно или письменно ответить минимум на 70% контрольных вопросов;
- уметь с нуля написать маленькую функцию с условием и обработкой ввода.

## Важный принцип

Сейчас скорость не оценивается. Оцениваются корректность, понимание и способность исправить ошибку после объяснения. Медленное самостоятельное решение полезнее быстрого скопированного.
