# Теория недели 0

Конспект читается последовательно. Не пытайся запомнить всё после первого чтения: запускай каждый пример, изменяй значения и наблюдай за результатом.

## 1. Программа, интерпретатор и выполнение кода

### Что такое программа

Программа — последовательность инструкций, записанных по правилам языка. Исходный код Python обычно хранится в файле с расширением `.py`.

```python
print("Первая инструкция")
print("Вторая инструкция")
```

В простом файле инструкции выполняются сверху вниз. Если выполнение остановилось из-за необработанной ошибки, следующие инструкции не выполнятся.

```python
print("Это будет выведено")
print(10 / 0)
print("До этой строки выполнение не дойдёт")
```

### Интерпретатор

Интерпретатор Python запускает код. Упрощённо можно думать так:

1. Python читает исходный файл.
2. Проверяет синтаксис.
3. Преобразует код во внутреннее представление.
4. Выполняет инструкции.

Фраза «Python — интерпретируемый язык» полезна для начала, но она упрощает реальную модель: например, CPython сначала создаёт bytecode. Подробности не нужны для недели 0.

### Script и интерактивный режим

В интерактивном режиме можно выполнить одну инструкцию и сразу увидеть результат. Файл удобнее для программы, которую нужно сохранять, проверять и изменять.

Интерактивный режим хорош для короткого эксперимента:

```python
2 + 3
```

`.py`-файл нужен для всех сдаваемых упражнений.

### Текущая рабочая папка

Относительные пути считаются от текущей рабочей папки, а не обязательно от папки, где визуально открыт файл. На неделе 0 достаточно помнить об этом, если Python сообщает, что файл не найден.

### Вывод через `print()`

```python
print("Toyota")
print(31_000)
print("Цена:", 31_000, "USD")
```

`print()` умеет выводить несколько значений, автоматически разделяя их пробелом.

Полезные параметры:

```python
print("Toyota", "Camry", sep=" - ")
print("Загрузка", end="...")
print("готово")
```

Не используй сложные параметры `print()` без необходимости. Они приведены, чтобы вывод не казался магией.

### Комментарии

```python
# Это комментарий
price = 31_000  # Короткий комментарий к причине, а не пересказ кода
```

Хороший комментарий объясняет **почему**, а не повторяет **что** делает очевидная строка.

Плохо:

```python
# Умножаем цену на количество
total = price * quantity
```

Полезнее:

```python
# В отчёте нужна стоимость всей партии, а не одной машины
total = price * quantity
```

### Отступы

В Python отступ обозначает блок кода:

```python
if price > 0:
    print("Корректная цена")
```

Стандартный отступ — четыре пробела. Не смешивай табуляцию и пробелы.

## 2. Значения, объекты, имена и присваивание

### Значение и переменная

Для начала переменную можно считать подписанным местом, где находится значение:

```python
price = 31_000
```

Более точная модель: `31_000` — объект, а имя `price` связано с этим объектом. Присваивание `=` создаёт или меняет связь имени со значением.

```python
price = 31_000
price = 29_000
```

После второй строки имя `price` указывает на новое значение.

### `=` не означает математическое равенство

```python
stock = 5
stock = stock - 1
```

Вторая строка читается так:

1. Взять текущее значение `stock`.
2. Вычесть 1.
3. Связать имя `stock` с результатом.

Сокращённая форма:

```python
stock -= 1
```

Другие формы:

```python
total += price
quantity *= 2
```

### Динамическая типизация

Имя не закрепляется навсегда за одним типом:

```python
value = 10
value = "десять"
```

Python разрешает это, но без причины менять смысл и тип одной переменной не следует: код становится труднее понимать.

### Правила имён

Имя:

- может содержать буквы, цифры и `_`;
- не может начинаться с цифры;
- чувствительно к регистру;
- не может совпадать с ключевым словом.

```python
car_price = 31_000
buyer_balance = 50_000
```

`price`, `Price` и `PRICE` — разные имена.

Для обычных переменных и функций используется `snake_case`. Константы по соглашению пишутся прописными буквами:

```python
MAX_DISCOUNT_PERCENT = 30
```

Python технически не запрещает изменить такую переменную. Прописные буквы сообщают намерение разработчика.

### Ключевые и встроенные имена

Нельзя назвать переменную ключевым словом, например `if`, `for`, `def`, `return`.

Не следует перекрывать встроенные имена:

```python
# Неудачные имена
str = "Camry"
input = 10
sum = 50
```

После такого присваивания вызов соответствующей встроенной функции может перестать работать в текущей области видимости.

## 3. Основные типы

### `int`

`int` хранит целые числа:

```python
year = 2024
quantity = 3
temperature = -5
```

Подчёркивания помогают читать большие литералы и не влияют на значение:

```python
price = 31_000
```

### `float`

`float` хранит числа с плавающей точкой:

```python
discount = 7.5
rating = 4.8
```

Некоторые десятичные дроби нельзя точно представить в двоичном формате:

```python
print(0.1 + 0.2)
```

Поэтому:

- `float` подходит для многих приблизительных измерений;
- деньги в серьёзном приложении хранятся через `Decimal` или в минимальных целых единицах;
- `round()` форматирует/округляет результат, но не исправляет модель хранения денег;
- прямое сравнение результатов сложных float-вычислений через `==` может быть ненадёжным.

На неделе 0 цены в упражнениях задаются целыми долларами, чтобы внимание оставалось на основах.

### `str`

Строка — последовательность символов:

```python
brand = "Toyota"
model = 'Camry'
```

Одинарные и двойные кавычки создают строку одинаково. Выбирай вариант, который уменьшает экранирование:

```python
message = "Покупатель сказал: 'Беру'"
```

Специальные последовательности:

```python
print("Первая строка\nВторая строка")
print("Марка:\tToyota")
print("Кавычка: \"")
```

Полезные операции:

```python
full_name = brand + " " + model
length = len(full_name)
upper_name = full_name.upper()
clean_name = full_name.strip()
```

Методы строк не изменяют исходную строку, а создают новую:

```python
model = " camry "
clean_model = model.strip()
```

Индекс начинается с нуля:

```python
model = "Camry"
first = model[0]
last = model[-1]
part = model[0:3]
```

Подробно срезы будут закрепляться на неделе 1.

### `bool`

Логический тип имеет два значения:

```python
is_available = True
email_confirmed = False
```

Обычно `bool` появляется в результате сравнения:

```python
has_stock = stock > 0
```

### `None`

`None` означает отсутствие значения:

```python
selected_supplier = None
```

Проверять `None` принято через `is`:

```python
if selected_supplier is None:
    print("Поставщик не выбран")
```

Не путай `None`, `0`, `False` и пустую строку: это разные значения, хотя в условии все они считаются ложными.

### Просмотр типа

```python
print(type(31_000))
print(type("31000"))
```

Строка из цифр не становится числом автоматически.

### Преобразование типов

```python
price_text = "31000"
price = int(price_text)

discount_text = "7.5"
discount = float(discount_text)

message = str(price)
```

Некорректное преобразование вызывает исключение:

```python
int("Toyota")
```

### `bool()` и истинность значений

Ложными считаются, в частности:

- `False`;
- `None`;
- числовой ноль;
- пустая строка.

```python
print(bool(0))
print(bool(""))
print(bool("0"))
```

Строка `"0"` непустая, поэтому она истинна.

## 4. Выражения и арифметика

Выражение вычисляет значение:

```python
price * quantity
```

Инструкция выполняет действие:

```python
total = price * quantity
```

### Операторы

```python
addition = 10 + 3
subtraction = 10 - 3
multiplication = 10 * 3
division = 10 / 3
floor_division = 10 // 3
remainder = 10 % 3
power = 10 ** 3
```

`/` всегда возвращает результат деления, обычно `float`. `//` выполняет деление с округлением вниз, а не просто «удаляет дробную часть»:

```python
print(-5 // 2)  # -3, потому что округление идёт вниз
```

Остаток `%` связан с целочисленным делением. На практике он часто применяется для проверки чётности и циклических правил:

```python
is_even = number % 2 == 0
```

### Приоритет

Упрощённый порядок:

1. Скобки.
2. Возведение в степень.
3. Умножение, деление, `//`, `%`.
4. Сложение и вычитание.
5. Сравнения.
6. `not`, затем `and`, затем `or`.

Если выражение трудно читать, используй промежуточные переменные и скобки.

```python
discount_amount = price * discount_percent / 100
final_price = price - discount_amount
```

### Округление

```python
rounded = round(12.345, 2)
```

Python использует стратегию округления, при которой результат на точной половине может округляться к ближайшему чётному. Для финансовых правил округление должно быть явно согласовано и позднее реализовано через `Decimal`.

### Деление на ноль

```python
10 / 0
```

Вызывает `ZeroDivisionError`. Нужно заранее определить, допустим ли ноль по смыслу задачи.

## 5. Ввод и форматирование вывода

### `input()`

```python
name = input("Введите имя: ")
```

Результат `input()` всегда имеет тип `str`, даже если введены только цифры.

```python
age_text = input("Возраст: ")
print(type(age_text))
```

Преобразование выполняется явно:

```python
quantity = int(input("Количество: "))
```

Такая короткая запись удобна, но при ошибке нельзя отдельно увидеть исходную строку. Во время обучения полезнее разделять действия:

```python
raw_quantity = input("Количество: ")
quantity = int(raw_quantity)
```

### Очистка ввода

Пользователь может добавить пробелы:

```python
model = input("Модель: ").strip()
```

Пустая строка после `strip()` обычно означает отсутствие обязательного значения.

### F-строки

```python
message = f"{brand} {model}: {price} USD"
```

Форматирование числа:

```python
print(f"Цена: {price:.2f} USD")
```

`.2f` означает вывод двух знаков после десятичной точки. Это формат отображения, а не изменение способа хранения значения.

### Данные и представление

Не добавляй `" USD"` к числу во время расчётов:

```python
# Плохо для расчётов
price = "31000 USD"

# Лучше
price = 31_000
print(f"{price} USD")
```

## 6. Сравнения и логика

### Сравнения

```python
price == 31_000
price != 31_000
price < 40_000
price <= 40_000
price > 20_000
price >= 20_000
```

`=` присваивает, `==` сравнивает.

Python поддерживает цепочки сравнений:

```python
is_valid_discount = 0 <= discount_percent <= 100
```

### `and`

```python
can_buy = stock > 0 and balance >= price
```

Оба условия должны быть истинными.

### `or`

```python
needs_attention = stock == 0 or price <= 0
```

Достаточно одного истинного условия.

### `not`

```python
if not email_confirmed:
    print("Подтвердите email")
```

### Короткое замыкание

Python вычисляет логическое выражение слева направо и может не вычислять оставшуюся часть:

```python
if quantity != 0 and total / quantity > 10_000:
    print("Высокая средняя цена")
```

Если `quantity == 0`, деление не выполняется. Порядок условий может защищать от ошибки.

### Истинность и явные проверки

```python
if model:
    print("Название введено")
```

Это проверяет непустую строку. Для учебного кода иногда яснее написать условие явно:

```python
if model != "":
    print("Название введено")
```

Главное — понимать, что именно проверяется.

## 7. Ветвление

```python
if stock <= 0:
    print("Нет товара")
elif balance < price:
    print("Недостаточно денег")
else:
    print("Покупка разрешена")
```

Выполняется только первая подходящая ветвь. Поэтому сначала обычно проверяют более важные ошибки или более узкие условия.

### Независимые `if`

Два отдельных `if` могут выполнить два блока:

```python
if stock <= 0:
    print("Нет товара")

if balance < price:
    print("Недостаточно денег")
```

Цепочка `if`/`elif`/`else` выбирает только одну ветвь. Выбор зависит от требуемого поведения.

### Вложенные условия

```python
if stock > 0:
    if balance >= price:
        print("Покупка разрешена")
```

Вложенность допустима, но несколько логических условий или ранний выход из функции часто читаются проще.

### Граничные значения

Всегда решай заранее:

- цена, равная балансу, разрешена или нет;
- нулевое количество допустимо или ошибочно;
- границы скидки включаются или исключаются;
- остаток, равный требуемому количеству, достаточен или нет.

Большая часть ошибок начинающих появляется на `0`, точном равенстве и отрицательных значениях.

### Условное выражение

Короткий выбор значения можно записать так:

```python
status = "доступен" if stock > 0 else "нет в наличии"
```

Не используй такую форму для длинной логики.

## 8. Циклы

### `for` и `range`

```python
for number in range(5):
    print(number)
```

Будут выведены числа от 0 до 4. Правая граница не включается.

```python
range(1, 6)       # 1, 2, 3, 4, 5
range(2, 11, 2)   # 2, 4, 6, 8, 10
range(5, 0, -1)   # 5, 4, 3, 2, 1
```

### Счётчик и накопитель

```python
total = 0

for number in range(1, 6):
    total += number
```

`total` — накопитель. Он создаётся до цикла, обновляется внутри и используется после цикла.

### `while`

```python
attempts = 3

while attempts > 0:
    print(attempts)
    attempts -= 1
```

Перед каждой итерацией проверяется условие. Если оно изначально ложно, тело не выполнится ни разу.

### Бесконечный цикл

```python
while True:
    command = input("Введите exit для выхода: ")
    if command == "exit":
        break
```

`while True` допустим, когда внутри есть понятное и достижимое условие выхода.

### `break`

Немедленно завершает ближайший цикл:

```python
while True:
    value = input("Введите stop: ")
    if value == "stop":
        break
```

### `continue`

Пропускает остаток текущей итерации:

```python
for number in range(1, 6):
    if number == 3:
        continue
    print(number)
```

### `else` у цикла

У циклов Python существует `else`, который выполняется, если цикл закончился без `break`:

```python
for number in range(1, 4):
    if number == 10:
        break
else:
    print("Значение не найдено")
```

Это необязательная возможность. На неделе 0 достаточно уметь прочитать такой код.

### Частые ошибки циклов

- правая граница `range` не включается;
- счётчик `while` не изменяется;
- накопитель случайно обнуляется внутри цикла;
- `break` стоит раньше полезной операции;
- условие невозможно выполнить;
- один и тот же код дублируется до и внутри цикла.

## 9. Функции

### Определение и вызов

```python
def calculate_total(price, quantity):
    return price * quantity


total = calculate_total(31_000, 2)
```

Код тела функции выполняется при вызове, а не при самом `def`.

### Параметр и аргумент

В определении `price` — параметр. В вызове `31_000` — аргумент.

```python
def show_price(price):
    print(price)


show_price(31_000)
```

### Позиционные и именованные аргументы

```python
def calculate_total(price, quantity):
    return price * quantity


calculate_total(31_000, 2)
calculate_total(price=31_000, quantity=2)
```

Именованные аргументы полезны, когда назначение числа неочевидно.

### Значение по умолчанию

```python
def calculate_price(price, discount_percent=0):
    return price - price * discount_percent / 100
```

Параметры без значения по умолчанию должны находиться раньше параметров со значением по умолчанию.

Тема опасных изменяемых значений по умолчанию появится после изучения коллекций.

### `return`

`return`:

- возвращает значение;
- немедленно завершает функцию;
- без явно указанного значения возвращает `None`.

```python
def validate_price(price):
    if price <= 0:
        return False

    return True
```

Код после выполненного `return` недостижим.

### `print()` против `return`

```python
def bad_total(price, quantity):
    print(price * quantity)
```

Такой результат нельзя удобно использовать в следующем вычислении, потому что функция возвращает `None`.

```python
def calculate_total(price, quantity):
    return price * quantity
```

Теперь вызывающий код решает, напечатать, сохранить или сравнить результат.

### Область видимости

```python
def calculate_total(price, quantity):
    total = price * quantity
    return total
```

`total` существует локально внутри вызова функции. Не привязывай бизнес-расчёты к глобальным переменным: передавай зависимости параметрами.

### Чистая функция

Упрощённо чистая функция:

- зависит только от аргументов;
- возвращает результат;
- не меняет внешний мир.

Расчёт цены удобно писать чистой функцией. Чтение `input()` и вывод `print()` — отдельные операции взаимодействия с пользователем.

Такое разделение облегчает проверку:

```python
def calculate_total(price, quantity):
    return price * quantity


price = int(input("Цена: "))
quantity = int(input("Количество: "))
print(calculate_total(price, quantity))
```

### Одна ответственность

Функция `read_positive_integer()` должна читать и проверять число. Функция `calculate_total()` должна считать. Функция `print_receipt()` должна выводить чек. Если одна функция делает всё, её трудно проверять и исправлять.

### Аннотации типов

```python
def calculate_total(price: int, quantity: int) -> int:
    return price * quantity
```

Аннотация описывает ожидание, но Python обычно не проверяет её автоматически во время выполнения.

### Docstring

```python
def calculate_total(price: int, quantity: int) -> int:
    """Возвращает стоимость указанного количества автомобилей."""
    return price * quantity
```

Не нужно писать docstring, который просто повторяет имя функции. Он полезен для контракта, единиц измерения или неочевидного правила.

### Точка входа

```python
def main():
    print("Программа запущена")


if __name__ == "__main__":
    main()
```

На неделе 0 достаточно использовать этот шаблон в итоговом проекте. Подробно импорты и значение `__name__` будут изучаться позже.

## 10. Ошибки, исключения и проверка данных

### Синтаксическая ошибка

```python
if price > 0
    print(price)
```

Python не может разобрать программу. Выполнение не начинается.

### Runtime-ошибка

```python
price = int("Toyota")
```

Синтаксис корректен, но операция невозможна для конкретного значения.

### Логическая ошибка

```python
discount_amount = price - discount_percent
```

Программа может выполниться без исключения, но формула неверна. Логические ошибки обнаруживаются тестовыми примерами и анализом результата.

### Как читать traceback

Читай с конца:

1. Тип исключения.
2. Сообщение.
3. Последний фрагмент, относящийся к твоему файлу.
4. Номер и содержимое строки.

Длинный traceback не означает десятки независимых ошибок. Часто это путь к одной исходной проблеме.

### `try` и `except`

```python
raw_price = input("Цена: ")

try:
    price = int(raw_price)
except ValueError:
    print("Введите целое число")
```

В `try` помещай только операцию, которая ожидаемо может вызвать обрабатываемую ошибку. Слишком большой блок затрудняет поиск причины.

### Несколько исключений

```python
try:
    result = total / quantity
except ValueError:
    print("Некорректное число")
except ZeroDivisionError:
    print("Количество не может быть нулём")
```

В этом искусственном примере `ValueError` не возникнет, если преобразование находится вне `try`. Обрабатывай только реально возможные исключения в выбранном блоке.

### `else` и `finally`

```python
try:
    price = int(raw_price)
except ValueError:
    print("Некорректная цена")
else:
    print("Цена прочитана")
finally:
    print("Попытка обработки завершена")
```

- `else` выполняется, если исключения не было;
- `finally` выполняется независимо от результата.

На неделе 0 достаточно понимать этот код. `finally` чаще нужен для освобождения ресурсов, которые будут позже.

### Почему нельзя писать пустой `except`

```python
try:
    price = int(raw_price)
except:
    price = 0
```

Такой код может скрыть неожиданные ошибки и превратить проблему в неверные данные. Лови конкретное исключение.

### Проверка формата и бизнес-правила

Это разные уровни:

1. `"abc"` нельзя преобразовать в число — ошибка формата.
2. `-100` можно преобразовать, но отрицательная цена запрещена — нарушение бизнес-правила.

```python
try:
    price = int(raw_price)
except ValueError:
    print("Цена должна быть числом")
else:
    if price <= 0:
        print("Цена должна быть положительной")
```

### `raise`

Функция может сообщить о недопустимом значении через исключение:

```python
def validate_discount(discount_percent):
    if not 0 <= discount_percent <= 100:
        raise ValueError("Скидка должна быть от 0 до 100")
```

Для недели 0 достаточно уметь прочитать и один раз применить `raise`. Политика собственных исключений будет позже.

### `assert`

```python
assert calculate_total(10, 3) == 30
```

`assert` удобен для учебных проверок и тестов. Он не заменяет проверку пользовательского ввода или бизнес-валидацию: assertions могут быть отключены при специальном режиме запуска Python.

## 11. Отладка

### Пошаговый подход

1. Воспроизведи ошибку на минимальном вводе.
2. Запиши ожидаемый и фактический результат.
3. Найди первую строку, где значения расходятся.
4. Проверь типы и промежуточные значения.
5. Измени одну причину.
6. Повтори старые сценарии после исправления.

### Временный диагностический вывод

```python
print("DEBUG price:", price, type(price))
```

Подписывай значение, иначе несколько чисел в выводе не помогут. После исправления удаляй временную диагностику.

### Debugger

Точка останова позволяет остановить программу, посмотреть значения и выполнить строки по одной. На неделе 0 достаточно научиться:

- поставить breakpoint;
- продолжить выполнение;
- сделать шаг через строку;
- посмотреть локальные переменные.

### Не исправляй случайными изменениями

Сформулируй гипотезу: «`input()` вернул строку, поэтому сложение работает как объединение текста». Затем проверь `type(value)` и только после этого меняй код.

## 12. Стиль и читаемость

### Базовые правила

- четыре пробела для отступа;
- `snake_case` для переменных и функций;
- пробелы вокруг бинарных операторов;
- пустые строки между функциями;
- одна смысловая операция на строку;
- понятные английские имена в коде;
- сообщения пользователю могут быть на русском;
- отсутствие мёртвого и закомментированного старого кода.

```python
final_price = base_price - discount_amount
```

Хуже:

```python
x=bp-da
```

### Магические числа

Если число является правилом, дай ему имя:

```python
MAX_DISCOUNT_PERCENT = 30
```

Обычные `0`, `1`, `100` в очевидной формуле не всегда требуют константы.

### Повторение кода

Если одна формула повторяется, вынеси её в функцию. Но не создавай функцию ради одной очевидной строки, если она не выражает отдельное понятие.

### Ранний выход

Несколько проверок можно сделать без глубокой вложенности:

```python
def can_buy(balance, price, stock):
    if stock <= 0:
        return False

    if balance < price:
        return False

    return True
```

На неделе 0 важнее ясность, чем минимальное количество строк.

## 13. Ручная проверка программы

Для каждой функции подготовь таблицу:

| Сценарий | Вход | Ожидание |
|---|---|---|
| Обычный | положительные значения | корректный результат |
| Нижняя граница | 0 | заранее выбранное поведение |
| Точное равенство | баланс равен цене | покупка разрешена |
| Ошибка формата | текст вместо числа | понятное сообщение и повтор ввода |
| Нарушение правила | отрицательная цена | отказ принимать значение |

Проверяй не только happy path. Ошибка часто живёт в границе диапазона или неправильном типе.

### Простые проверки функций

```python
assert calculate_total(10, 2) == 20
assert calculate_total(10, 0) == 0
```

Перед написанием проверки вычисли ожидаемый результат самостоятельно.

## 14. Частые ошибки недели 0

- ожидать, что `input()` вернёт число;
- путать `=` и `==`;
- сравнивать число со строкой;
- забывать двоеточие после `if`, `for`, `while`, `def`;
- использовать неправильный отступ;
- забывать обновить условие `while`;
- перепутать включённую и исключённую границу `range`;
- печатать результат внутри функции вместо `return`;
- продолжать выполнение после обнаружения недопустимых данных;
- ловить все исключения пустым `except`;
- использовать `float` как надёжную модель денег;
- скрывать ошибку значением `0`;
- писать всю программу внутри одного огромного блока;
- использовать непонятные имена `a`, `b`, `x1`;
- проверять только один успешный сценарий.

## 15. Словарь недели

- **аргумент** — конкретное значение при вызове функции;
- **ветвление** — выбор выполняемого блока по условию;
- **выражение** — код, вычисляющий значение;
- **инструкция** — выполняемое действие;
- **интерпретатор** — программа, выполняющая Python-код;
- **исключение** — объект, сообщающий об ошибочной ситуации;
- **итерация** — одно выполнение тела цикла;
- **литерал** — значение, записанное прямо в коде, например `10` или `"Camry"`;
- **параметр** — имя входного значения в определении функции;
- **переменная** — имя, связанное со значением;
- **тип** — набор возможных значений и операций над ними;
- **traceback** — путь вызовов до места необработанного исключения;
- **функция** — именованный повторно используемый блок поведения;
- **граничный случай** — значение на границе допустимого диапазона;
- **бизнес-правило** — ограничение предметной области, например запрет отрицательной цены.
