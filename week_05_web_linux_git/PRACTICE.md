```python
    ...
```

- при совпадении валидатора верни `304` и пустое body;
- иначе `200`, JSON body, `ETag` и `Cache-Control`;

## Обязательные сценарии

1. `GET` классифицирован как safe и idempotent.
2. `POST` не объявлен idempotent автоматически.
3. Повторный `DELETE` может дать другой status, оставаясь idempotent по intended effect.
4. `401` и `403` различаются.
5. `405` сопровождается `Allow` в примере ответа.
6. Кириллица даёт `Content-Length` по bytes.
7. `Accept: */*` допускает JSON.
8. `Accept: text/html` отклоняется учебным JSON endpoint.
9. ETag match даёт `304` без body.
10. Персональная цена помечена `no-store`.

## API contract

### `GET /health`

- `200 OK`;
- JSON `{"status": "ok"}`;
- `Cache-Control: no-store`.

### `GET /cars`

- `200 OK`;
- список машин из неизменяемого in-memory каталога;
- необязательные query-параметры `available=true|false` и `max_price`;
- денежные значения сериализуются строками;
- неверные параметры дают `400`;
- публичный результат получает явно выбранную cache policy.

### `GET /cars/{car_id}`

- `200 OK` для существующей машины;
- `404 Not Found` для отсутствующей;
- path parameter обязан быть положительным целым, иначе `404` либо `400` по заранее описанному и последовательно применённому правилу.

### `POST /quotes`

Вход:

```json
{
  "car_id": 1,
  "quantity": 2,
  "discount_percent": 10
}
```

Правила:

- только `Content-Type: application/json`;
- body не больше 4096 bytes;
- корень JSON — object;
- `bool` не считается integer;
- `car_id` существует;
- `1 <= quantity <= 20`;
- `0 <= discount_percent <= 30`;
- расчёт выполняется через `Decimal`;
- денежный результат — JSON string;
- ответ содержит `Cache-Control: no-store`;
- API только рассчитывает quote и не создаёт запись, поэтому успешный status обоснуй в `README.md`.

## Общие правила HTTP

- неизвестный path → `404`;
- известный path с неверным method → `405` и `Allow`;
- несовместимый `Accept` → `406`;
- слишком большое body → `413`;
- неверный media type → `415`;
- битый JSON → `400`;
- корректный JSON с неверными полями → `422`;
- неожиданная ошибка → generic `500` без traceback;
- JSON responses имеют `Content-Type: application/json; charset=utf-8`;
- `Content-Length` считается по bytes;
- добавь `X-Content-Type-Options: nosniff`;
- каждому ответу назначается или передаётся безопасный request id;
- logs не содержат body, secrets или traceback в ответе;
- CORS headers не добавляются без реального cross-origin требования.

## Архитектурные обязанности

### `catalog.py`

- неизменяемые исходные данные;
- поиск и фильтрация;
- расчёт через `Decimal`;
- не знает WSGI environ и HTTP statuses.

### `errors.py`

- небольшая иерархия ожидаемых application errors;
- ошибка содержит безопасный public code/message;
- внутренние подробности не уходят клиенту.

### `responses.py`

- сериализация JSON;
- status line;
- обязательные headers;
- точный `Content-Length`;
- единый формат ошибки.

### `security.py`

- лимит body;
- content negotiation/media type checks;
- validation request id;
- никаких auth/JWT/OAuth реализаций.

### `application.py`

- WSGI callable;
- routing;
- request parsing;
- преобразование ожидаемых ошибок в HTTP response;
- safe fallback для неожиданных ошибок;
- `start_response()` вызывается один раз.

### `checks.py`

- вызывает WSGI app напрямую;
- формирует `environ` через стандартную библиотеку;
- захватывает status, headers и body;
- не запускает TCP server;
- завершает процесс с ненулевым status при провале проверки.

### `server.py`

- необязательный ручной запуск через `wsgiref.simple_server`;
- bind только `127.0.0.1`;
- запуск только под `if __name__ == "__main__":`;
- явное предупреждение: development/reference server, не production.

1. Health возвращает `200` и `no-store`.
