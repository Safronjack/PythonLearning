## Цель недели

Перейти от локальных Python-программ к пониманию среды backend-разработчика. К концу модуля ученик должен уметь:

- объяснить путь запроса от URL до ответа приложения;
- различать URL, DNS, IP, порт, TCP, TLS и HTTP;
- читать структуру HTTP request/response;
- выбирать методы и статусы по семантике;
- понимать safe, idempotent и cacheable как разные свойства;
- работать с headers, media type, cookies, cache control и JSON;
- различать REST, RPC и GraphQL на прикладном уровне;
- объяснить границу web-server/application через WSGI и ASGI;
- распознавать CORS, CSRF, XSS, SQL injection и SSRF;
- различать session auth, JWT и OAuth 2.0;
- выполнять безопасные базовые операции в Unix/Linux shell;
- понимать процессы, сигналы, права, environment и логи;
- использовать Git: working tree, index, commits, branches, merge, rebase, conflict и revert;
- описывать изменение в формате pull request;
- различать назначение Agile, Scrum, Kanban, CI/CD, TDD, BDD и DDD;
- схематично описывать безопасные потоки регистрации и входа;
- собрать локальный WSGI JSON API без Django и внешних библиотек.

## Границы сложности

На этой неделе не требуются:

- администрирование DNS-зон или выпуск настоящих TLS-сертификатов;
- packet capture и низкоуровневая реализация TCP;
- поддержка HTTP/2 или HTTP/3 своими руками;
- production-ready web server;
- полноценный REST framework;
- реализация OAuth provider, JWT-подписи или password storage;
- эксплуатация уязвимостей против внешних систем;
- обход SSRF-защиты;
- root-доступ, `sudo`, изменение swap или системных конфигураций;
- публикация Git-репозитория и создание реального удалённого PR;
- сложный Git internals, submodules и переписывание общей истории;
- Django, DRF и база данных.

Agile/Scrum/Kanban, CI/CD, TDD/BDD и DDD изучаются обзорно: на этой неделе требуется понимать назначение, различия и типичные ошибки применения. Полноценная автоматизация pipeline, тестовая стратегия и предметное моделирование будут отработаны на следующих этапах.

`wsgiref.simple_server` используется только как локальная учебная reference implementation и не считается production-сервером. ASGI изучается через минимальный callable и симуляцию событий без установки ASGI server.

## Критические ошибки

- небезопасная операция выполняется через GET;
- API всегда отвечает `200`, скрывая тип ошибки;
- JSON-тело читается без разумного ограничения размера;
- CORS используется как замена аутентификации или авторизации;
- пользовательский ввод объединяется со строкой SQL;
- приложение выполняет запрос по произвольному пользовательскому URL;
- JWT, OAuth или password hashing реализуются самодельной криптографией;
- секрет попадает в код, commit, вывод или лог;
- учебный сервер объявляется пригодным для production;
- shell-скрипт работает с путями вне учебной папки или использует `sudo`;
- переменные shell раскрываются без кавычек там, где это меняет аргументы;
- права без причины выставляются через `chmod 777`;
- учебный процесс остаётся работать после сценария;
- Git-лаборатория инициализируется в корне проекта;
- применяется `git reset --hard`, принудительная публикация или удаление истории;
- конфликт считается решённым без проверки содержимого и нового commit;
- в итоговом сервисе traceback или внутренняя ошибка возвращается клиенту;
- ученик не может объяснить границу между HTTP, WSGI/ASGI и приложением.
