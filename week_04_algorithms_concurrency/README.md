# Неделя 4: алгоритмы, память и конкурентность

Статус: **подготовлена заранее и заблокирована**.

Начало разрешается только после полного зачёта недель 0–3 и явного допуска в `week_03_oop_typing/ASSESSMENT.md`. Текущей активной работой остаётся неделя 0.

## Цель недели

Научиться выбирать алгоритмы и модель выполнения по измеримым причинам, а не по догадке. К концу модуля ученик должен уметь:

- оценивать время и дополнительную память алгоритма через Big O;
- отличать лучший, средний, худший и амортизированный случаи;
- реализовывать линейный и бинарный поиск;
- применять стек, очередь, deque, heap и базовые обходы дерева;
- понимать свойства основных алгоритмов сортировки;
- использовать рекурсию с корректным базовым случаем;
- объяснять ссылки на объекты, reference counting и циклический GC в CPython;
- измерять время и память через `timeit`, `cProfile` и `tracemalloc`;
- различать concurrency и parallelism, I/O-bound и CPU-bound задачи;
- понимать практическую роль GIL в CPython 3.11;
- выбирать последовательное выполнение, потоки, процессы или `asyncio`;
- различать coroutine function, coroutine object, Task и Future;
- не блокировать event loop синхронной долгой операцией;
- реализовать одну очередь задач последовательно, через потоки и через `asyncio`.

## Границы сложности

На этой неделе не требуются:

- математические доказательства асимптотических границ;
- заучивание реализаций всех сортировок;
- красно-чёрное или AVL-дерево своими руками;
- графовые алгоритмы уровня олимпиадного программирования;
- lock-free структуры;
- сложная диагностика deadlock/livelock/starvation;
- shared memory и ручной IPC между процессами;
- собственный event loop, transports или protocols;
- продвинутая отмена, `shield`, группы исключений и сложные схемы `TaskGroup`;
- реальные сетевые запросы и внешние сервисы;
- утверждение, что ускорение обязательно произойдёт на любой машине;
- особенности свободнопоточных сборок новых версий Python.

Целевая среда модуля — CPython 3.11.9. Для безопасной переносимости process-функции объявляются на верхнем уровне модуля, а запуск защищается `if __name__ == "__main__"`.

## Критические ошибки

- основной сценарий не запускается или алгоритм зацикливается;
- бинарный поиск обращается за границы или пропускает допустимую границу;
- заявленная сложность принципиально неверна и ученик не может объяснить подсчёт операций;
- сортировка неожиданно изменяет входные данные вопреки контракту;
- рекурсия не имеет достижимого базового случая;
- вывод о всей памяти делается только по `sys.getsizeof()` внешнего контейнера;
- результат считается корректным только потому, что программа выполнилась быстро;
- поток меняет общее составное состояние без понятной синхронизации;
- поток или процесс остаётся незавершённым;
- `ProcessPoolExecutor` запускается без безопасной точки входа;
- coroutine создана, но не awaited и не запланирована как Task;
- внутри coroutine используется `time.sleep()` для имитации ожидания;
- event loop блокируется CPU-heavy или обычной блокирующей операцией;
- исключение worker теряется и итог ошибочно помечается успешным;
- конкурентный код предполагает стабильный порядок завершения;
- ученик объясняет GIL как гарантию потокобезопасности.
